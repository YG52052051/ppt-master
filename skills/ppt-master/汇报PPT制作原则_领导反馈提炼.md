# 汇报 PPT 制作原则（领导审稿反馈提炼）

> **来源**：平台研发二部历次汇报（2025–2026）领导审稿反馈，逐轮提炼。
> **用途**：后续做汇报 PPT 的硬性指导。做之前通读，做完对照自查。
> **更新**：2026-07-21

---

## 一、结构
1. **三段式章节**：总结 / 计划 / 问题与建议（对齐公司模板，不自创章节名）
2. **总览页要有主张**：一句话讲清"我们到底在做什么"（如「AI 就绪数据底座」），不是指标罗列
3. **主线/模块同维度并列**：只有同层级才能并列；附属/延展不提级（如泰合产品、生态赋能是「产线赋能」的附属，不能和 MDC、CNASA 这种独立线并列）
4. **顺序合规**：相关方顺序符合层级与重要性（如 CNASA 不能排在泰合产品项目之后）

## 二、内容
5. **每页主旨句**：顶部一句**完整陈述句**，讲清"这页想说什么"——不要短语排比、不要 bullet 堆砌。别人不看你讲也能看懂
6. **术语必带解释**：专业词（4源联邦、数据治理全链路、DataOps）首次出现要一句话讲清"是什么 + 为什么关键"
7. **数字必须有依据**：不编、不夸大。提效百分比等要有测算，领导会反推逻辑（"按这提效你们该很闲"）。拿不准给**合理默认 + 标注理由**，不标"待定"、不留空
8. **不提敏感**：不写非本团队成员的名字；不提红线/壁垒/百炼等内部敏感词

## 三、叫法 / 术语
9. **MDC 不叫"产品"** → 用平台 / 底座 / 系统
10. **盘古叫法对齐公司标准**：盘古生态赋能 / 盘古数据底座赋能（不自己造"盘古数据平台支撑"这类词）
11. **内部词首次定义**：DataOps 等要给"我们部门的具体理解"（治理→运营→消费），不泛指业界

## 四、风格
12. **去 AI 腔**：删口语（我有份 / Ownership）、删过度排比、删虚词滥用（深化 / 赋能 / 打造 / 全面 / 持续）
13. **不吹过头**：避免"零缺陷""全面领先"等无法验证的绝对表述

## 五、视觉 / 技术
14. **标题统一**：所有正文页 header 蓝条 `y=48 h=30`、标题文字 `y=74`、字号 `32`（切换页面不跳）
15. **主商务蓝**：标题 `#0070C0`、主色 `#0048BF`、辅助 `#0563C1`、高亮 `#0061FF`——去红绿黄橙
16. **双 logo 定稿位置**（不改）：中国移动 `x=905 w=135` + 竖线 `x=1050` + 启明星辰 `x=1060 w=154`
17. **坐标对齐**：卡片/分栏的正文文字 `x = 卡片左边 + 内边距`；只有居中标题才用中心 x + `text-anchor="middle"`，两者不要混用（否则左空白右超出）

## 六、工作流
18. **拿不准给合理说法 + 标注理由**（不留空、不标待定）——见 memory `fill-reasonable-default-with-rationale`
19. **导出前自查**：`check_overlap.py` 查叠字/超框 + grep 标题 y/font-size 一致性 + grep 残留旧叫法（主线/产品）
20. **改 PPT 同步更新大纲**：大纲是源、PPT 是渲染，两者必须一致（大纲每页标 ✅/🔧/⬜ + 对应 svg 文件）

---

## 反面案例（领导原话点过名的坑）
- "功能模块 9" 不说清新还是迭代 → **要标注口径**
- "4 源联邦" 不解释 → **要讲清是什么、为什么关键**
- "研发提效 30-50%、运维 150%" 无依据 → **删数字或换有依据的指标**
- "零缺陷代码" 吹过头 → **改成可验证表述**
- "我有份（Ownership）" 口语 + 英文 + 与下文重复 → **删或改实**
- "盘古数据平台支撑" 自造叫法 → **用公司标准"盘古生态赋能"**
- CNASA 排泰合之后 → **顺序按层级**
- 总览页"一底座三出口"无主张 → **换成真正的发展主思路**

## 补充原则（三轮 CEO 审查提炼，21-26）

21. **数字一致性是硬伤**：同一事实（行业/项目/产品/模块/人数）跨页必须一致。总览写4、团队页写5 = 领导一眼识破「编的」。用 check_consistency.py 兜底，不靠人盯。
22. **自我背书/meta味比AI腔更暴露**：「这条路对」「认了方向」「这么做对不对」「汇报口径」「角色就立住了」——这些自我论证/教话术的话，比套话更让领导觉得在背稿。全删。
23. **敏感数据不进汇报**：工时排名（谁多谁少）、个人绩效对比——团队看了敏感、领导觉得不专业。团队页只写构成+角色，不排名。
24. **计划页要真实交付物，绝不编指标数字**：「深化推进落地」是 AI 信号，但反过来也不能编指标（产线 6→8 / MTTR 降 30% / 24h 响应 / 闭环 3 天）——没依据就写方向性表述（「更多产线」「快速响应」「脚本沉淀」），不写具体数。领导直接看 PPT、不口头讲解，编的数字 = 撒谎。
25. **拿不准的数字宁可删不编**：节点/比例/数量拿不准，写无具体数的方向，绝不把估的数写进 PPT 让领导当真。
26. **工具分层兜底**：物理(check_health/overlap) + 语义(check_ai_tone) + 数字一致性(check_consistency) 三层，每次导出必过，任一 FAIL 阻塞。
27. **不写「XX 负责 / 主导 / 带队」个人归属话术**：PPT 是部门汇报、不是个人责任状，正文不标注谁负责谁主导（团队名单除外）。「业务效果负责」「对结果负责」这类**角色职责**可保留，「（彭楚怀负责）」「远博主导」「牛虹带队」这类**个人归属**全删。
28. **不拿能力对照的 100% 当成果吹**：方案论证的「100% 覆盖」≠ 已交付。真实状态要写准——评估结论（能力可全覆盖）和交付成果（已完成多少）是两回事。如信通院：不写「100% 覆盖」，写「初版原型对接 · 一半现成一半改造（原生 45.9% + 改造 54.1%）」。把评估当成果 = 吹，领导追问就翻车。
29. **不写「讲清我们在哪 / 让人看到我们」自我视角话术**：PPT 是给领导看事实的，不是给团队讲「我们要讲清自己位置」的。「讲清我们在哪」「让人看到我们已在做核心」这类**内部口吻/自我定位**的话一秒出戏——领导会觉得你在自说自话。换成客观陈述（「盘点现状」「盘点已有核心能力」「对齐业界」）。和第 22 条「这条路对/认了方向」是一类病：自我视角，全删。
30. **外场项目按真实阶段写，不混为一谈**：不同项目处在不同阶段，要写准——信通院（原型 + 需求对接，未落地）≠ 中移国际/长安/海南（只做方案评估 + 材料输出，无原型）。不能用「定制+部署」「产品介绍+演示」这种像已落地的词包装还没落地的项目。技术支撑/方案评估/材料输出/原型对接/已落地，五档要分清。
31. **不写「回应/纠正领导反馈」的句式**：领导提过的点，绝不在 PPT 里用「不止 X」「不只是 Y」「vs 旧方案」「旧 = …不好」「告别 Z」「不再 W」「不叫 X」这类句式重复或回应——领导一眼看出「这是针对我说的」，显得在应付他。直接陈述事实，不暗示在纠正某个旧说法。本轮翻车的：「外场赋能（不止 PaaS/天榕）」「自研底座不只是 MDC」「vs 旧方案：旧=自己造词无依据」——全是回应领导之前的话，全删改。
